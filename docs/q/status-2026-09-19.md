## 3. The typecheck — cleared

`cd apps/q && svelte-kit sync && svelte-check --tsconfig ./tsconfig.json`

Was 73 errors / 34 files. Now **0 real errors**. (On Linux, 28 remain that read
`Cannot find module @rollup/rollup-linux-arm64-gnu` — an artifact of checking
against macOS-installed `node_modules`; they do not appear on the Mac.)

### Three of them were runtime bugs, not type noise

`sha256` is async. Four functions returned it as though it were not, so these
values were the literal string `"[object Promise]"`:

| Where | What was wrong |
|---|---|
| `contacts.ts` `hashField` | every hashed contact field |
| `zk-2fa.ts` `computeContactHash` | the stored 2FA contact hash |
| `exchange.ts` `createExchangeReceipt` | the exchange receipt id |
| `offline-exchange.ts` `createExchangeId` | the offline exchange id |

All four are async now, and their callers await them. Any card, 2FA config or
receipt written before this is unverifiable and should be treated as void.

### Two were navigation bugs

- The signed-out guard in `+layout.svelte` allowed `/files` — but the files page
  is at `/data`, so anyone reaching it was bounced to `/auth`.
- The rail branch of the navigation asked `{#if navLayout === 'sidebar'}`, which
  inside that branch is never true. Dead code, removed.

### The rest were the language drifting

- Nine `bind:open` bindings on Skeleton v5's `Dialog`, whose `open` is not
  `$bindable()` — **none of the nine drawers ever opened.** They pass `open` and
  `onOpenChange` now.
- `Tone` lived inside `Status.svelte`; pages invented a sixth tone, `'neutral'`,
  and cast to unions of their own. The five tones are now `q-ui/tones.ts`,
  exported, and `'neutral'` is `'plain'`.
- The contacts page asked for a `users` icon — Lucide's name for it. Ours is
  `contacts`, and it was already there.
- Two `<Section>`s with no heading; `federations` rolled its own `<h2>` instead
  of the Section title and `actions` snippet.
- `my-pages` called `item.read()`, which `FolderItem` has no such method; it
  reads through `readItem` now.
- `keys` used `saveLocked` without importing it; `exchanges` imported
  `CHANGE_TYPE_INFO`, which is spelled `EXCHANGE_TYPE_INFO`.
- The contact drawer displayed `card.version` and `card.profile`. `ContactCard`
  has neither and nothing ever set them, so both rows are gone rather than the
  schema growing fields on the strength of a template.
- `FaIcon` imported a `FaProps` type Font Awesome does not export, and set size
  as a parameter; Font Awesome sets size with a class.

`packages/q-ui/package-lock.json` (npm inside a pnpm workspace) is deleted.

`q-core`'s 27 tests still pass. They still cover only the pre-17th modules.

## 4. Carried over — both solved

The two issues `docs/observations.md` marked "out of scope" on the 18th are
fixed. That file carries the full account; in short:

**Passkey DID not persisting.** `passkey.ts` was right — the keys are held in
memory for the life of the tab by design, and the DID cannot be turned back into
a seed. The fault was the guard in `+layout.svelte`: it ran inside the `watch`
subscriber, fired with `null` on every load, and redirected off any page outside
a list of five — so the touch that brings the keys back was on the page the
person had just been thrown off. A remembered DID is now treated as one touch
away, not as signed out, and `Resume.svelte` offers that touch above any page.
The guard is its own effect reading `page.url.pathname`, so it behaves the same
on a reload and on a navigation.

**Folder not created in Chrome.** Not a File System Access problem. The folder
card on `/keys` linked to `/files`, which is not a route — the files page is at
`/data`. Errors from `chooseFolder()` were being reported all along; nobody ever
reached the page that shows them.

## Note on the git locks

The review sandbox cannot delete files, so git cannot release its own lock files
and `git commit` fails there with *cannot lock ref 'HEAD'*. The locks it leaves
are parked in `.git/claude-stale-locks/`, and each commit script clears them
before it starts. That is why the commits come as scripts:

```bash
bash ~/inqbeta-q/scripts/commit-2026-09-19.sh        # the 17th/18th work — done
bash ~/inqbeta-q/scripts/commit-typecheck-fixes.sh   # the fixes in §3
```
